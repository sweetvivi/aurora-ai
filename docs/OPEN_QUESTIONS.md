## 真实上游可用性（2026-10-20 实测）

- 对话：`gpt-6-astra`、`qwen3.8-max` 可用；`deepseek-v4-pro-0813` 上游 429 限流，同一密钥的 `deepseek-v4.1-flash` 正常，是否切换默认别名待定
- 生图：`gpt-image-2.5` 文生图与图生图（`/images/edits`）均可用，已验证「原图加红帽子、其余保持不变」
- 视频：`grok-imagine-video` 文生视频与图生视频均已打通。**必须使用第 7 组「生视频测试1」密钥**——旧分组会拒绝内联图片（`image url must be http(s) or asset://`），且该分组不接受 `resolution` 字段（带上直接 422，代码已做去掉重试）
- 已移除：`doubao-seedream-4-0`、`doubao-seedance-1-0-pro`、`doubao-seedance-2-0` 从 `DEFAULT_MODELS` 删除，`/api/v1/models` 不再返回，前端下拉不会再出现；后续接入豆包时需要重新注册并配置火山方舟的 Key 与 Base URL（当前网关无 `/api/v3`，实测 404）
- 生图第二渠道（2026-10-20 已接入）：`grok-imagine-image` / `grok-imagine-image-2.0` 走新分组，必须固定 `response_format: b64_json`——回链 `imgen.x.ai` 在本机 DNS 被污染（解析到 108.160.165.53），无法直接下载
- 能力差异（前端与后端已按此过滤）：`gpt-image-2.5` 支持保真编辑（`/images/edits`），Grok 生图传入图片只会被当作参考、整幅重绘（实测猫图加红帽子后背景从雪窗变成秋日长椅），因此 `supportsImageEdit: false`，不会出现在「智能修图 / 局部编辑 / 商品图处理」的模型列表里
- 视频能力差异：两个 Grok 视频模型 `supportsImageInput: true`（可图生视频），但 `supportsLastFrame`、`supportsVideoInput` 均为 false，视频工作台的首尾帧与参考视频入口已标为「暂无可用模型」；如需这两类能力要补对应模型/密钥
- 画布连线与素材（2026-10-20 已统一规则，待用户确认口径）：每个生成节点的素材 = 它的直接来源节点产物，不沿链穿透；文本节点只贡献提示词，不携带图片；从视频节点生成图片时截取首帧作为参考图；「视频 → 视频」当前无通道。参考产品 6.png 的视频面板有「首帧 / 尾帧」两个槽位，本实现目前是单素材首帧，是否要做多素材槽位待定
- 视频的理解与再生成（2026-10-20）：画布「视频 → 文案」改为抽 2% / 50% / 98% 三张关键帧送多模态模型（对话接口只收 `image/*`），文案节点可再派生「文生视频」节点。**这只覆盖画面，不含音频、节奏与镜头连续性**；要真正理解视频需要支持视频输入的模型（当前网关没有）。「以某张尾帧收尾」仍要等 `supportsLastFrame` 的模型，目前只能在 prompt 里描述结尾画面
