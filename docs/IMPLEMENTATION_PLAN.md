# 极光AI 实施计划

更新时间：2026-10-17

## 1. 执行目标

项目采用“演示优先、商用可升级”的路线。所有实现先完成可验证的垂直切片，再扩展产品线，不为演示写死数据模型，也不在 M0 阶段一次性铺设参考产品的全部路由。

当前主要开发工具为 Codex。除非用户明确决定切换，否则不因工具或模型变化重新讨论产品方向。

## 2. 协作执行规则

### 第一档：自动执行

以下操作在 `C:\Users\Administrator\Desktop\project2` 和对应 `outputs` 内直接执行：

- 读取项目、搜索代码和查看 Git 状态
- 修改项目内文件
- 运行本地测试、类型检查和构建
- 启动本地开发服务器并检查页面

### 第二档：先说明再做

执行前说明操作、影响范围、生成文件和回退方式，随后继续执行：

- 安装项目依赖
- 修改项目级配置
- 批量整理项目文件
- 请求第三方接口
- 启动 Docker、PostgreSQL、Redis 等额外服务
- 使用本地数据库

### 第三档：单独确认

以下操作必须暂停并等待用户明确回复“继续”：

- 递归删除或批量移动
- 修改系统设置、注册表、服务或防火墙
- 全局安装工具
- 停止不属于本项目的进程
- 清库或执行破坏性数据库迁移
- 部署、域名或 DNS 操作
- 支付相关操作
- 上传文件到外部服务
- 读取、写入或导出密钥
- Git 强制推送
- 将本地服务暴露到公网

普通 `git push` 也先说明目标远端、分支和提交范围，再等待确认。

## 3. 里程碑

### M0 工程基础

目标：建立可以持续开发、测试和回退的前后端工程骨架。

范围：

- pnpm workspace 和根级脚本
- Vue 3 前端骨架
- NestJS 后端骨架
- PostgreSQL、Redis 和 BullMQ 基础设施
- Prisma 基础模型和迁移流程
- 健康检查、统一响应和异常结构
- 请求 ID、结构化日志和配置校验
- provider adapter、模型注册表和密钥引用抽象
- 五套 Shell 和基础路由占位
- 测试、代码检查和 GitHub Actions 最小 CI
- `.env.example`，不写入任何真实密钥

M0 不做：

- 真实模型调用
- 注册、邮箱验证和第三方登录
- 真实支付
- 管理后台
- 视频、音频、股票和完整绘图工作台
- 参考产品 232 个路由的批量实现

M0 验收：

- `pnpm install` 可重现安装
- 前端和后端均可本地启动
- `/health` 返回稳定的健康状态
- PostgreSQL 和 Redis 可通过 Docker Compose 启动
- 五套 Shell 可访问，桌面端和移动端无明显布局错误
- 前后端类型检查、测试和构建通过
- 最小 CI 可以完成安装、构建和测试
- 仓库不包含密钥、Token、Cookie 或用户数据

### M1 第一条垂直切片

目标：完成从登录、选模型、真实流式对话、积分结算到历史记录的首条闭环。

范围：

- 开发登录和邮箱登录基础
- Access Token 与 Refresh Token
- 用户、会话和权限边界
- 积分账本、冻结、结算、失败退回和幂等键
- 真实 OpenAI 兼容 LLM provider
- 对话 SSE、历史、消息和模型选择
- 上游错误分类、重试提示和可恢复状态
- 文件上传基础与本地存储 adapter
- 图片异步任务状态机
- 生图在 M1 使用确定性 Mock provider，并完成真实异步任务闭环；真实生图 Key 在后续阶段接入
- 生图测试固定使用 1、3 号 Key；4 号 Seedance Key 只保留给后续视频生成
- 对话测试使用 2 号 DeepSeek Key；真实密钥只通过后端环境变量注入
- 任务历史、结果查询和失败处理

M1 验收：

1. 用户登录。
2. 选择 `openai-gpt-6-astra`。
3. 完成真实流式对话。
4. 积分冻结并正确结算。
5. 上游失败时积分退回。
6. 会话和消息可查询。
7. 图片任务可提交并查询状态。

### M2-M7 后续方向

- M2：第二模型供应商、支付沙箱、积分和订单完善。
- M3：最小管理后台，覆盖用户、模型和订单。
- M4：视频、音频、声音克隆及更多登录方式。
- M5：对象存储、股票系统、部署准备和内容安全。
- M6：性能、可观测性、备份和正式内测准备。
- M7：真实支付、退款、发票、会员到期和多端权益同步。

具体范围在进入对应里程碑前重新确认，不在 M0 提前实现。

当前用户优先级修正：智能体、图片和视频是参考产品重点，但现阶段先完成智能体和图片相关的功能与界面实现，视频暂时后置；其他板块先保留导航和入口位置。

## 4. 工程边界

- 前端只使用模型别名，不暴露上游真实模型名。
- 上游模型名映射保存在 `provider_model` 字段。
- 真实密钥只通过本机环境变量注入，仓库只提供 `.env.example`。
- 首期文件保存在本地磁盘，但必须通过存储 adapter 隔离，便于切换 MinIO 或 OSS。
- 支付订单使用状态机和幂等键，前端不能直接修改支付结果。
- 积分不能只依赖用户表余额，必须保留可审计流水和任务关联。
- 复杂生成能力采用提交任务、查询结果和失败退回模式。
- 所有页面复用 Shell、工具注册表和工作台能力，不逐页复制实现。
